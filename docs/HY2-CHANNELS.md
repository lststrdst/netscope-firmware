# HY2 Channels — серверы из подписки

Я добавил в Quick Setup отдельный список HY2-серверов: импорт подписки,
контроль UDP, ручной выбор и автоматический резерв. Интерфейс продолжает
визуальный стиль NETSCOPE, без дополнительного UI-фреймворка на роутере.

[Редактируемый макет в Figma](https://www.figma.com/design/rpSpM5mXmSmBqVEum5w3FH?node-id=41-61)
использует демонстрационные имена и показатели, не историю домашней сети.

## Как пользоваться

1. Откройте **Быстрая настройка VPN → Серверы и каналы**.
2. Вставьте HTTPS-подписку, обёртку Happ или одиночную HY2-ссылку.
3. Нажмите **Добавить серверы**. В группу попадут только HY2; остальные
   поддерживаемые узлы будут перечислены в результатах разбора.
4. Для первой установки включите один HY2-профиль через обычную проверку
   мастера, затем голосовой маршрут и его автозапуск. Импорт не делает этого сам.
5. Нажмите **Проверить серверы**, затем **Авто** или **Выбрать** у нужного узла.
   Ручной выбор переводит группу в ручной режим.

Группа ограничена восемью HY2. Повторный идентичный профиль не создаёт второй
узел. URL подписки не сохраняется для фонового обновления: сейчас это разовый
импорт. Другие протоколы не становятся резервом HY2 автоматически.
Удаление черновика, включённого в группу, заблокировано: контроллер не должен
внезапно потерять конфигурацию резерва. Редактор состава группы пока в плане.

## Как выбирается сервер

- Проверяется сквозной UDP через SOCKS5 с проверкой STUN transaction ID.
- Активный узел проверяется через работающий транспорт; для резервов по очереди
  запускается короткоживущий клиент без TUN и без изменения маршрутов.
- Два последовательных отказа активного узла допускают переход на резерв.
  Резерв должен иметь две успешные свежие проверки и выйти из 120-секундного
  карантина после своей ошибки.
- Три последовательных результата выше 250 мс допускают смену только при
  улучшении минимум на 30% и не чаще одного раза в пять минут.
- Низкий RTT одного случайного запроса не заставляет исправный канал «прыгать».
- История ограничена 30 переключениями, метрики — 20 пробами на узел, в RAM.
  Это **потери контрольных проб и изменение их RTT**, не потери аудио и не
  встроенный показатель задержки Discord.

История и метрики сбрасываются при перезагрузке; выбор сервера и режим
хранятся на USB. Один внешний STUN-сервис остаётся общей точкой проверки:
несколько независимых контрольных целей — отдельная задача.

## Безопасность и восстановление

Голосовой маршрут остаётся узким: целевой UDP Telegram/Discord. Группа не
меняет LAN, L2TP, системный default route, маршруты игр или веб-трафик VLESS.
Mieru запускается только при явном включении в конфигурацию автозапуска.

Переключение сериализовано. Предыдущий профиль записывается в приватный
журнал до остановки транспорта. Новый профиль подтверждается после проверки
процесса, TUN, UDP и маршрута. Неудача возвращает предыдущую конфигурацию;
если и она не работает, голосовое перехватывание снимается — fail-open.
Прерванный переход восстанавливается boot-reconciler. Ручное выключение
имеет приоритет над автореконнектом. Текущий звонок при смене сервера может
переподключиться: бесшовность не обещается.

Контроллер напрямую наблюдается procd и защищён process-scoped lock через
[nixio.File](https://openwrt.github.io/luci/api/modules/nixio.File.html).
Нельзя оставлять между procd и контроллером отдельного родителя `flock -o`:
после остановки такого родителя дочерний контроллер может остаться работать.

API использует существующую авторизацию LuCI и POST/CSRF для команд.
В status отдаются только названия, локальные ID, метрики и история — не
пароли, URI, ключи и приватные YAML. Сама группа и профили хранятся на USB
в закрытых каталогах, файлы имеют режим 600. Установка пакета не включает
службу автоматически.

## Реализация и проверки

- `netscope_channels.lua`: импорт группы и безопасная проекция status;
- `netscope_channel_policy.lua`: чистая логика выбора;
- `netscope-channels`: ограниченные пробы и очередь команд;
- `netscope-voice-boot`: переключение, журнал и recovery;
- `channels.js` / `channels.css`: список узлов в существующем Quick Setup.

Проверки: Python source/packaging tests, Node parser tests, Lua policy tests,
изолированный shell-тест успешного перехода, отказа запуска/UDP, прерванного
перехода, ручной паузы и защиты чужого профиля. На домашнем стенде выполнены
переходы между тремя HY2 с проверкой UDP и маршрута. Реальная перезагрузка,
отключение USB и продолжительные звонки ещё не входят в завершённую матрицу.

## Что остаётся

- независимый автоматический выбор VLESS для браузера/YouTube;
- несколько контрольных UDP-целей и измерение пропускной способности;
- обновление сохранённой подписки и полноценный редактор состава группы;
- длинные звонки, реальный reboot и поздний USB на отдельном стенде;
- повторная полная проверка кнопок и мобильной страницы на живом LuCI.
